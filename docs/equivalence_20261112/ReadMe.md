# 恢复版与历史 RoboDojo 实验的一致性核验

日期：2026-11-12。核验实例：1015。

## 结论

在本次历史数据覆盖范围内，采用旧实验的有效配置、固定原始输入和 API
返回内容，恢复版得到相同的业务输出。没有发现恢复引起的业务结果差异。
这不是对未测试输入、不同配置或未来 API 响应的数学保证。

本次付费 API 调用为 0。回放程序禁止 socket 网络连接，只使用磁盘上的
原始响应。新输出均位于 `/mnt/workspace/script/review_equivalence_20261112`，
没有覆盖旧实验。

异常筛查的 3499 条中，2054 条是实例重建前保存的结果，1445 条来自之后
1013 的续跑。业务统计均为：正常 2015、异常候选 349、不确定 1135。
原失败项 `robodojo_episode_001102` 的 6 份可读取原始响应仍报
`Unknown subtask ID`，并非恢复后新增的失败。

VLM 回放包含原实验补跑路径中的 2 次成功请求，并沿用这些请求记录的
32768 输出预算，而不是错误地用首次失败请求替代最终结果。

## 明确排除的差异

- 回放输出目录、图像发送缓存路径及由路径派生的请求签名。
- 生成时间、运行耗时、吞吐等运行元数据。
- 旧 DINO 首尾实验的 summary 未写 `feature_mode`；新输出显式写
  `dual_cls`。比较汇总业务值时按旧配置补充该字段；任务和成员结果未忽略字段。
- 47 次历史尝试仅留下输入消息，因挂载中断没有保存完整响应，无法重放
  它们的 API 输出。这些 episode 后续的完整重试/续跑结果已核验。

完整重试回放需要按原 messages 中是否带反馈识别进程续跑的重新开始，
不能把跨进程的 attempt 编号简单拼成一次连续重试。初版测试脚本对此处理
不正确，修正测试器后 77 个 episode 全部通过；业务框架代码未修改。

## 配置边界

恢复的 `scene_clustering_vlm/config.yaml` 是默认模板：任务并发为 4，输出
目录为 `two_round_v1`。历史全量实验使用并发 16 和单独实验目录。
本次回放使用历史实验快照配置，而不是默认模板；未为此修改业务配置。

没有重新请求 API 来证明模型生成稳定性，没有全量回归浏览器交互，也
没有把此次核验扩展为对附属 `vlm_subtask_reasoning` 历史实验的等价证明。
